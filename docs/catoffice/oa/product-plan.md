# CatOffice OA · 功能规划

> 状态：**规划 v0.1**（只规划、不编码）。本文是 OA 服务端产品的功能清单与
> 边界；架构见 [architecture.md](architecture.md)，接口契约见
> [contracts.md](contracts.md)，桌面端侧见 [../oa-plan.md](../oa-plan.md)。

## 1. 一句话定位

**文档环节最强的自托管 OA**：审批、客户、任务等管理场景由客户部署在
自有内网，其中所有「文档」的环节——套版生成、编辑、签发留痕、盖章、
归档——复用 CatOffice 引擎完成；客户已有的钉钉 / 企微 / 泛微 / CRM 通过
连接器接入，不与之对抗。

与竞品的差异只有一条但足够硬：**所有 OA 的文档编辑器都是外挂短板，
我们的引擎（docx-engine 字节级往返、GB/T 9704 公文、印章弧形字）就是
产品本身**。

## 2. 战场切分

| 战场 | 主导者 | 我们怎么打 |
| --- | --- | --- |
| 通用审批（请假 / 报销 / 采购） | 钉钉 / 企微 / 泛微 | **不进**。只做连接器与通知通道 |
| 公文 / 合同等「单据即文档」流程 | 泛微 / 致远（文档环节弱） | **主战场**：签发、会签、套版、盖章、归档全链 |
| CRM | 销售易 / 纷享 / 客户自建 | 提供轻量 CRM（客户 / 联系人 / 商机 + 文档关联），且一切对象可从外部 CRM 同步而来 |
| 任务 / 协作 | 钉钉 / 飞书 | 轻量看板 + 文档派生待办，不做重型项目管理 |
| 知识 / 归档 | 各种网盘 | 文档归档：版本、全文检索、标准格式导出 |
| 政务 / 信创 | 泛微 / 数科 | 国密 / OFD（跟随桌面端 C5 决策）、隔离网部署、等保配合 |

## 3. 模块清单

图例：`M0` 底座必装 · `M1` 首批可拆模块 · `M2` 后续 · `N` 明确不做。

### 3.1 身份与组织（M0，唯一底座）

| 功能 | 优先级 |
| --- | --- |
| 用户 / 组 / 角色；角色权限覆盖模块与操作两级 | M0 |
| 目录同步：LDAP / AD / 钉钉 / 企微通讯录（只读联邦，单向入） | M0 |
| 自维护用户兜底（无外部身份源的小型内网） | M0 |
| 设备码登录（与桌面端 / catspark 同构）+ 会话管理 | M0 |
| SSO（OIDC / CAS，政务常见） | M2 |
| 组织架构展示与人员搜索 | M0 |

### 3.2 审批工作流（M1）

| 功能 | 优先级 |
| --- | --- |
| 流程引擎：串签 / 会签 / 或签 / 条件分支 / 超时催办 / 撤回 | M1 |
| 表单设计器（先模板化预置表单，不先做自由拖拽设计器） | M1 预置 / M2 设计器 |
| **公文签发流程**：拟稿 → 核稿 → 会签 → 签发 → 用印 → 归档；意见落正文留痕 | M1（旗舰场景） |
| **合同会签流程**：合同模板套版 → 审批 → 用印 → 归档 | M1 |
| 审批事件 webhook 出站（接钉钉 / 企微通知） | M1 |
| 通用表单审批的钉钉 / 企微双向连接器（在它们发起，单据文档仍由我们套版） | M2 |
| 流程可视化设计器（BPMN 级） | N（预置模板够用，不追 Ow） |

### 3.3 客户管理 CRM（M1，轻量）

| 功能 | 优先级 |
| --- | --- |
| 客户 / 联系人 / 商机三对象；自定义字段 | M1 |
| **文档关联**：合同 / 报价 / 方案挂在客户与商机对象上，一键套版生成 | M1（差异点） |
| 邮件合并生产线：数据源（本 CRM / 上传 xlsx / 外部 CRM API）× 模板 → 批量文档 | M1 |
| 外部 CRM 连接器（销售易 / 纷享 / 自建 REST）：对象同步，本系统可只作文档层 | M2 |
| 销售漏斗 / 报表 | M2（轻量） |
| 呼叫 / 邮件营销 | N |

### 3.4 任务（M1，轻量）

| 功能 | 优先级 |
| --- | --- |
| 看板 / 列表 / 负责人 / 截止日期 | M1 |
| **文档派生待办**：从文档抽取的义务 / 事项生成任务，回链原文位置 | M1（差异点） |
| 审批流产生的任务（如「核稿」自动成为经办人任务） | M1 |
| 甘特 / 依赖 / 工时 | N |

### 3.5 文档归档（M1）

| 功能 | 优先级 |
| --- | --- |
| 版本历史、全文检索（含 OCR 后文本） | M1 |
| 存储后端：本地盘 / S3 兼容 / WebDAV | M1 |
| 归档四性检测接口（真实性 / 完整性 / 可用性 / 安全性，电子档案口径） | M2 |
| 借阅 / 权限流程 | M2 |

### 3.6 集成与开放（贯穿）

| 功能 | 优先级 |
| --- | --- |
| 文档桥（桌面端真编辑器打开 / 保存回传，见 contracts.md） | M1 |
| `catoffice://` 深链与第三方 OA 网页「用办公猫打开」按钮组件 | M1 |
| webhook 入站 / 出站 + REST API（全部契约化） | M1 |
| 钉钉 / 企微通讯录与通知连接器 | M1 |
| 审计日志：与桌面端 C1 同构的哈希链 JSONL，服务端汇聚查询 | M0 |
| 管理控制台（模块启停 / 权限 / 同步源 / 存储配置） | M0 |

### 3.7 明确不做（N）

IM / 日历 / 邮件 / HR 业务（薪资考勤绩效）/ 工单系统本体 / BI 报表平台 /
低代码平台 / 视频会议。防膨胀裁决规则见第 7 节。

## 4. 商业分层

| 层 | 内容 | 对应桌面端 |
| --- | --- | --- |
| **OA 基础** | M0 底座 + 任选一模块（审批或归档），单 Docker | 桌面工作台可用 |
| **OA 标准** | M0 + M1 全模块 | + 全部模块卡片 |
| **OA 政务** | 标准 + 国密 / OFD / 隔离网交付 / 等保配合 / 公文包深化 | + 信创桌面端形态 |
| **连接器订阅** | 外部 CRM / 钉钉企微深度连接器按年订阅 | 桌面端零改动 |

定价原则与桌面套件一致：不自建的部分不收自建的钱（连接器按集成价值收），
文档引擎能力是溢价核心。

## 5. 分期

| 阶段 | 范围 | 出口标准 |
| --- | --- | --- |
| **OA-0** | M0 底座（身份 / 审计 / 控制台）+ 设备码登录 + manifest + 文档桥 | 桌面端工作台在 mock 与真实实例两端到端走通 |
| **OA-1** | 审批（公文签发 / 合同会签两条预置流）+ 服务端模板套版 + 归档最小集 | 一份合同从 CRM 数据到套版 → 会签 → 盖章 → 归档全程不出内网 |
| **OA-2** | CRM + 任务 + 钉钉 / 企微连接器 + 外部 CRM 连接器 | 客户可在保留钉钉的前提下把文档环节整体迁入 |
| **OA-3** | SSO / 政务档（国密 OFD 跟随桌面 C5）/ 借阅与四性检测 | 首个政务试点验收 |

## 6. 与桌面端的关系

- 桌面端只认识 manifest + 桥协议 + Web 视图（见 [../oa-plan.md](../oa-plan.md)
  防膨胀条款）；**OA 新增任何模块不得要求桌面端发版**。
- OA 单独部署、不装任何桌面端时必须完全可用：Web 预览 + 标准 OOXML
  导出是基线，桌面编辑器是增强——这是「可单独部署」的验收定义。
- 引擎包（`docx-engine` 等）以 npm 包形式被 OA 服务端依赖，主仓保持
  引擎与编辑器的纯净；OA 建独立仓库，契约包 `@catoffice/contracts`
  双仓共享。

## 7. 防膨胀裁决规则

任何新模块 / 新功能提案，按序回答四问，任一答「否」即不进本产品：

1. 它是**文档环节**或身份 / 审计 / 控制台底座的一部分吗？（通用审批、
   IM、HR 业务在第一问即出局）
2. 客户既有系统不能更好地承担它吗？（能承担 → 做连接器）
3. 它能与底座拆开单独部署、单独售卖吗？（不能拆的巨型耦合不进）
4. 它让「文档环节最强」这个定位变深了吗？（只让安装包变大即否决）

## 8. 风险

| 风险 | 对策 |
| --- | --- |
| 被「再做一个 OA」的惯性拖进通用审批红海 | 第 7 节第一问硬裁；预置流程只收单据即文档类 |
| 服务端引擎与桌面引擎漂移 | 引擎只从主仓 npm 依赖，OA 仓不改 fork |
| 自建 CRM 与客户既有 CRM 数据双写冲突 | 定位为「可只作文档层」：对象同步单向入，本系统增量字段最少化 |
| 模块拆分沦为口头承诺 | 「底座 + 单模块」独立部署进 OA-0 验收项 |
| 政务合规工作量低估 | 国密 / OFD / 四性检测全部押后到 OA-3 且跟随桌面端 C5 决策 |
