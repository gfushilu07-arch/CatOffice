## 1. 一句话定位

办公猫是一款 **AI 原生、本地优先、格式不破坏** 的办公套件：在 Word / Excel / PowerPoint / PDF 的真实文件上工作，而不是在旁边开一个聊天框。它以开源 GenOffice 为引擎起点，用自有品牌、国产模型与中国办公场景，去抢 WPS 的日常桌面、补 Microsoft 365 在「本地、隐私、价格、AI 深度编辑」上的空档。

**不是**「再做一个功能清单更长的 Office」。Office 用三十年、上万人堆出来的功能面，一年内追平是幻觉。办公猫要赢的是三件事：

1. **打开别人的文件，保存回去，对方用 Word / WPS 打开看不出破绽。**
2. **AI 直接改文档结构**（段落、单元格、幻灯片、PDF 文本流），可回滚、可 diff。
3. **中文办公的及格线以上体验**：中文排版、公文、模板、国产模型、可私有化。

## 2. 为什么基于 GenOffice，而不是从零写，或去改 LibreOffice

### 2.1 GenOffice 已经做对的事

GenOffice（2026-08 开源）是目前唯一把「AI 编辑」当成一等公民、同时又认真做 **微软格式字节级往返** 的开源套件。关键资产：

| 资产 | 价值 |
| --- | --- |
| `packages/docx-engine` | `.docx` 解析为带 `docxIndex` 锚点的块树；只重写脏段落，其余 ZIP 条目原样拷贝 |
| Word 忠实分页 | 分页尽量落在 Word 会落的位置 |
| Sheets = Univer + Rust sidecar | UI 基于 Univer（Apache-2.0），xlsx 走 calamine + IronCalc，图表自研 Konva |
| 自研 `pptx-engine` / `pptx-render` | 母版、版式、智能参考线、非破坏裁剪、HarfBuzz 文本度量 |
| 真 PDF 编辑 | pdf.js + pdf-lib + PDFium WASM：改文本流和图片，不是盖注释层 |
| 本地 PDF → Office | `packages/pdf2docx`，不上传云端；扫描件走系统 OCR |
| `agent-core` + `ai-provider` | 多模型、流式、工具调用；BYOK 已支持 Claude / OpenAI / Gemini / DeepSeek / Kimi / GLM / Qwen / Doubao / Grok 等 |
| 安全基线 | `contextIsolation` + `sandbox` + IPC schema 校验 + 外链白名单 |
| 许可 | 主体 Apache-2.0，可商用、可闭源发行衍生二进制 |

这套「原文件是真相、编辑是补丁」的哲学，是 LibreOffice（ODF 为中心、OOXML 为过滤器）和多数 Web Office（内部模型再导出）都没做成的。对标 WPS / Office，**兼容性就是产品**。从这里起步，比从 Chromium + 自研排版从零做，至少省 18–36 个月的引擎时间。

### 2.2 必须立刻认清的限制

GenOffice 自己也写明：这是 **Alpha**。公开叙事里甚至有「一个工程师、一周、$10,000 token」的组装故事——真正的引擎年限在 Univer、Tiptap、pdf.js、PDFium 上，不在这。

| 限制 | 对办公猫的含义 |
| --- | --- |
| Alpha 质量、缺功能、有已知缺陷 | 不能把「能打开」当成「能交付」；要自建兼容性语料与回归 |
| 无实时协作、无云盘、无账号体系 | 这是 Office 365 / WPS 云的护城河，必须另开一条产品线，不能假装引擎里已经有 |
| 无移动端、Web 端不是产品形态 | 桌面 Electron 先行；Web/移动是 P1–P2 |
| Super Agent 绑 Genspark 积分 | 必须剥离，换成自有代理 + BYOK + 本地/国产模型 |
| `ee/` 目录是另一套企业许可 | **不要碰、不要拷贝、不要「 squint 一下当 Apache」** |
| 商标 | GenOffice、Genspark 是 Mainfunc, Inc. 商标；Apache-2.0 第 6 条不授权商标 |
| Tiptap / Univer 的 Pro 边界 | 开源核可用，部分高级扩展可能是商业许可，P0 做一次依赖许可证审计 |
| Linux OCR 缺失 | 中国 Linux / 信创用户必须补开源 OCR（PaddleOCR 等） |
| 无 VBA / 宏 / COM 加载项 | 第一年明确不做完整 VBA；提供 JS/Python 宏沙箱作为替代路径 |
| 无 Outlook / 日历 / 邮件 | **明确不做**。办公套件的坟墓是变成「全能平台」 |

### 2.3 为什么不选 LibreOffice / OnlyOffice 当底座

- **LibreOffice**：排版与宏很深，但 OOXML 往返一直是社区痛点；AI 是外挂；技术栈是 C++/LibreOffice 模块，和现代 AI agent 集成成本高。
- **OnlyOffice**：协作和 DOCX 兼容是长项，但核心是 Web 套件；AI 原生编辑、PDF 真编辑、字节级补丁都不是它的设计中心。
- **从零**：排版、公式、分页、PPT 母版、PDF 内容流，每一项都是「看起来简单、做完五年」。

结论：**Fork GenOffice 的 Apache-2.0 主体，立刻换品牌、换 AI 后端、换中文体验，把兼容性测试当成主产品。** 三个月后决定是「跟踪上游 cherry-pick」还是「硬分叉」——默认按硬分叉准备，只回挑引擎修复。

## 3. 法律、品牌与仓库红线（第一周就必须做完）

1. **Fork 后 48 小时内完成全面换肤**：应用名、包名、协议 scheme、更新服务器、图标、关于页、User-Agent、安装目录。
2. 保留 Apache-2.0 `LICENSE`、`NOTICE`、第三方声明；继续生成 third-party notices。
3. 删除或隔离 `ee/`，永远不要把企业许可代码混进主仓。
4. 去掉 Genspark 登录、设备码、gsk 工具端点、积分计费。AI 默认走：用户 BYOK → 自建兼容 OpenAI 的网关 → 可选本地模型。
5. 律师 / 合规过一遍：Electron 打包的字体（Liberation、Carlito、Caladea、Noto CJK）、PDFium、HarfBuzz WASM、Univer、Tiptap 扩展清单。
6. 对外话术：**「基于开源 GenOffice 引擎构建」**可以，**「GenOffice 中文版 / 官方发行」**不行。

建议仓库结构（monorepo 保持）：

```
apps/          docs, sheets, slides, pdf, markdown, shell
packages/      引擎与 AI（与上游同构，便于回挑）
brand/         自有品牌、文案、模板
compat/        兼容性语料、黄金文件、截图基线
skills/        AI 技能（公文、财报、教案、标书……）
desktop/       签名、更新、安装器、公证
```

## 4. 市场判断：对标谁、不对标谁

### 4.1 战场切分

| 战场 | 主导者 | 用户要什么 | 办公猫怎么打 |
| --- | --- | --- | --- |
| 桌面深度编辑 | Word / Excel / PPT、WPS 个人版 | 打开复杂文件、打印、公式、母版 | **主战场。** 兼容 + AI 编辑 |
| 云协作 | Microsoft 365、Google、WPS 云、飞书/钉钉文档 | 同时写、评论、权限、网盘 | P1 评论/异步；P2 真协同。不跟飞书拼 IM |
| 移动查看/轻改 | WPS、Office Mobile | 通勤看稿、签字、批注 | P1 查看+批注；P2 轻编辑 |
| 政务 / 国企 / 信创 | WPS、永中、数科 | 公文格式、国产化、私有化、等保 | P1 公文模板与排版；P2 信创适配 |
| 教育 / 学生 | WPS、Office 365 Education | 免费、模板、作业、PPT | 免费桌面 + 模板 + AI 限免 |
| 知识库 / Markdown | Notion、飞书、Typora、VS Code | 结构化写作、导出 Word | 已有 Markdown 应用，做「MD ↔ DOCX」本地闭环 |

### 4.2 竞品优劣势（决策用，不是营销用）

**Microsoft 365**

- 优势：格式金标准、协同、生态（SharePoint / Teams / Outlook / Power Query / VBA）、无障碍、企业合规。
- 劣势：订阅贵；AI（Copilot）偏旁路聊天与生成，对「改我这一段、保持样式」仍弱；中国区服务与合规摩擦；本地离线不是重心。

**WPS Office**

- 优势：中国桌面习惯、模板商店、PDF、公文、移动端、价格、渠道（预装）、中文排版。
- 劣势：闭源；云与隐私口碑两极；广告/会员转化伤个人用户；AI 多为套壳；国际格式边角仍翻车；对极客与外企「不够可信」。

**GenOffice（上游）**

- 优势：AI 进文档、字节往返、真 PDF、BYOK、开源。
- 劣势：Alpha、无协同、无中文场景、无品牌信任、无渠道。

**办公猫应占据的空位**

> 给「必须和 Word/WPS 来回传文件、又讨厌订阅与广告、希望 AI 真的改稿」的人：一份免费、可离线、可私有化的桌面套件。企业以后再卖协同、管理与专有技能。

## 5. 产品原则（写代码前钉死）

1. **原文件是真相。** 没碰过的字节不许改。样式、页眉、VBA 二进制、未识别的 OOXML 部件一律透传。
2. **AI 是编辑器，不是侧栏吉祥物。** 每次 AI 动作必须：作用范围可见、diff 可见、一键撤销、不改范围外内容。
3. **中文不是 i18n 的一个 locale。** 标点挤压、避头尾、字体回退、公文版式、日期数字是排版引擎的事。
4. **离线可用。** 没有网也能打开、编辑、保存、打印。AI 是增强，不是开门钥匙。
5. **少即是产品。** 第一年不做邮件、日历、IM、思维导图全家桶、音视频剪辑。
6. **兼容性有预算。** 每个版本必须跑黄金语料；回归失败不能发版。
7. **模型可替换。** 用户的 key、企业的网关、本地的 llama.cpp / vLLM，都是一等公民。

1. 打开客户发来的复杂 `.docx`（目录、脚注、修订、文本框），改两段，发回去。

3. 打开市场部 `.pptx`（母版、动画先透传），换标题、换图、导出 PDF。
4. 把扫描合同 PDF 变成可检索、可改数字的 Word。
5. 「把这一节改成给老板看的口吻，保持标题样式和编号。」
6. 「根据这个表生成 8 页路演，沿用公司母版。」
7. 「按 GB/T 9704 把这份报告套成公文。」

做不到 1–4，后面的 AI 都是演示。

## 7. 总体架构

### 7.1 运行时

沿用 GenOffice 的「一个壳 + 五个编辑器」Electron 架构，共享引擎包：

```
┌─────────────────────────────────────────────┐
│  办公猫Shell（首页 / 标签 / 主题 / 更新）     │
│  ┌─────┬─────┬─────┬─────┬─────┐            │
│  │文字 │表格 │演示 │ PDF │ Markdown │        │
│  └─────┴─────┴─────┴─────┴─────┘            │
│           同一套 AI 面板（作用域感知）        │
└─────────────────────────────────────────────┘
        │ IPC（zod schema）  │ 沙箱渲染进程
        ▼                    ▼
  packages/* 纯 TS 引擎     系统 OCR / 字体 / 打印
        │
        ├── docx-engine / pptx-engine / pdf2docx
        ├── sheets sidecar (Rust)
        └── agent-core → ai-provider → 网关 / BYOK / 本地
```

### 7.2 文字的往返（必须守住）

```
打开 docx → 按哈希归档原件（永不改）
         → 解析 word/document.xml 顶层块
         → 块树（docxIndex + 原始 XML 切片）
         → Tiptap 编辑（人工 + AI，脏标记）
保存     → 脏块生成 OOXML 片段（只引用已有样式）
         → 拼回原 document.xml（未脏块字节不变）
         → 重打 ZIP，其余条目原样拷贝
```

表格、演示同一哲学：内部模型可以丰富，**写回必须是窄补丁**。

### 7.3 办公猫要加的三层（上游没有、对标 WPS/Office 必需）

| 层 | 职责 |
| --- | --- |
| **Compat Lab** | 黄金文件库、像素/分页 diff、公式结果对比、CI 门禁 |
| **China Layout** | 中文排版规则、字体映射（宋体/黑体/楷体/仿宋 → Noto / 思源 / 方正授权）、公文版心 |
| **Cat Office Agent** | 技能包、作用域工具、本地 RAG、企业网关、审计；彻底替换 Genspark Super Agent |

### 7.4 以后的云（不要过早做进编辑器）

编辑器继续本地文件为中心。云是另一进程：

- 同步：文件级同步（自家盘 / WebDAV / S3 / 坚果云 / 对象存储）。
- 协同：先评论 + 建议模式；真 OT/CRDT 放到 P2。
- 账号：可没有账号用完整编辑器。登录只为同步、授权、计费。

## 14. AI 系统（办公猫的产品核）

### 14.1 架构

```
用户指令
  → 作用域解析（选区 / 当前页 / 整篇 / 工作簿 / 文件夹）
  → 技能路由（改写、公式、成组幻灯片、OCR、公文……）
  → 工具调用（读结构、搜本地、可选联网、生成图）
  → 补丁计划（block / cell / shape 级，而不是整文件重写）
  → 预览 diff + 快照
  → 用户确认或自动应用（可配置）
  → 撤销栈
```

禁止：把整份 docx 丢进模型再让它吐一个新 docx。那会毁掉往返哲学。

### 14.2 提供方策略

| 模式 | 谁用 | 数据 |
| --- | --- | --- |
| BYOK | 个人极客 | 流量直达用户选择的厂商 |
| 办公猫网关 | 普通个人 | 可关；走国内模型，合同约定不训练 |
| 企业网关 | 公司 | 客户 vLLM / 私有云，审计日志 |
| 本地 | 敏感行业 | Ollama / llama.cpp / 昇腾，完全离线 |

预置：DeepSeek、Qwen、Kimi、GLM、Doubao、MiniMax，以及 OpenAI 兼容自定义端点。Genspark 登录路径删除。

### 14.3 安全（AI 特有）

继承并加强上游：

- 幻灯片布局脚本：AST 解释器，禁止 `eval` / 网络 / IPC。
- AI HTML 导出：独立敌对 `BrowserWindow`。
- 提示注入：工具白名单、外网默认关、文件写入必须确认。
- 企业模式：禁止把文档正文发到非白名单主机。

### 14.4 技能包（可版本化、可关闭）

P0：通用改写、公式、成组幻灯片、PDF 问答、校对。  
P1：公文、合同、教案、财报、品牌套版。  
P2：行业包（医疗文书、招投标、学术期刊格式）。

技能用纯数据 + 少量 TS 工具描述，方便企业关掉或内部分发。

## 24. 风险

| 风险 | 可能 | 影响 | 对策 |
| --- | --- | --- | --- |
| 复杂 OOXML 边角无穷 | 高 | 高 | 透传优先、语料驱动、不宣称 100% |
| Univer / Tiptap 许可或 Pro 能力缺口 | 中 | 高 | 30 天审计；不行就换开源子集或自研窄模块 |
| Electron 内存与启动 | 高 | 中 | 延迟加载编辑器、共享进程策略、性能预算 |
| 上游 GenOffice 快速演进导致分叉成本 | 中 | 中 | 引擎包尽量少改 API；文档化补丁 |
| AI 胡改格式导致信任崩塌 | 高 | 高 | 补丁级应用、强制 diff、越界即失败 |
| 被当成「又一个套壳 ChatGPT」 | 高 | 中 | 演示永远先展示往返，再展示 AI |
| 协同做早拖垮编辑器 | 高 | 高 | 架构隔离；1.0 不做实时 |
| 商标 / 宣传口误 | 中 | 高 | 对外 FAQ 与贡献者指南写死 |
| 信创认证周期 | 高 | 中 | 不把认证当 1.0 门槛 |
| 人力低估公式与分页 | 高 | 高 | 编制见第 21 节；砍功能不砍门禁 |

## 25. 成功指标

### 1.0（约第 9 月）

- 黄金语料往返通过率 ≥ 95%（按桶加权，合同/公文桶 ≥ 98%）。
- A 档函数与 Excel 一致率 ≥ 99%。
- 种子用户「愿意把办公猫当默认打开方式」≥ 40%。
- AI 选区任务：人工抽检越界率 < 1%。
- 崩溃率：每小时活跃 < 0.5 次可恢复崩溃，0 次丢文件。

### 18 个月

- 月活桌面用户（自有渠道，不靠预装吹牛）。
- Pro 转化 2–5%（健康区间，不靠广告弹窗）。
- 至少 3 个付费私有化试点（含公文或法律场景）。
- Web 只读链接可发给不会装桌面的人。

## 26. 宣传与渠道（克制）

- 开源核心引擎（Apache-2.0）可继续公开，换品牌后的发行版可双许可，但不要制造「开源诱饵」。
- 内容：兼容性翻车对比视频、AI diff 录屏、公文一键套版。不要打「全面替代 Office」。
- 渠道：开发者社区、高校、律师/咨询垂直、Linux 用户、隐私向媒体。预装电脑是 WPS 的地盘，早期不要烧这个。
- 话术禁止：官方 GenOffice、100% 兼容、中国版 Copilot、永久免费企业私有化。

## 27. 建议的正式品牌方向（未决）

工作名「办公猫」：文书的枢纽。英文 Cat Office 或另选中性词（Helix / Quill / Oriole 一类，需商标检索）。

必须满足：全球可注册、不碰 GenOffice/Genspark/WPS/Office 视觉、中文两字好念、图标在 16px 可识别。

## 28. 一页结论

1. **Fork GenOffice，立刻换品牌、换 AI 后端、建兼容性实验室。**
2. **第一年赢在：格式往返 + 中文办公 + 进文档的 AI。** 不要赢在功能数量。
3. **协同、移动、信创分期。** 编辑器永远可离线。
4. **免费无广告做入口，网关、技能、私有化做收入。**
5. **没有黄金语料门禁，就没有 1.0。**

若只记住一件事：用户把文件发给仍在用 Word 和 WPS 的人——那一次保存，决定办公猫是办公软件，还是又一个演示 Demo。

## 附录 C · 公文 P1 范围（GB/T 9704）

- 版心：A4，上 37mm 下 35mm 左 28mm 右 26mm（按现行国标核对）
- 字体：标题方正小标宋、正文仿宋_GB2312、数字 Times，映射到已授权或开源等价并在缺字时警告
- 要素：份号、密级、紧急程度、红头、发文字号、签发人、标题、主送、正文、附件说明、发文机关署名、成文日期、印章占位、附注、抄送、印发机关
- 检查器：字号、行距、空行、标题断行、日期格式
- AI：把自由草稿填进要素，不直接「生成红头图」冒充公章
