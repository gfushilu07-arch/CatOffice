# 印章素材库与电子签章管理（SA 线）方案

> 状态：**规划**。SA1 边缘检测已落地。印章素材库与电子签章统一纳入
> **签章管理模式**（同一种管理面、两种安全等级），但二者能力与法律
> 效力有本质差异：素材库章是公开分发、无法律效力的视觉资产；签章是
> CA 证书背书、可产生"可靠电子签名"的签名实体。统一管理框架见 §一，
> 能力/效力边界对照与法律依据见 §二。

## 一、统一签章管理模式：同一管理面、两种安全等级

签章管理采用**统一注册、按级启用**的模型：所有印章（公开素材章、用户
自制章、CA 背书签章）都在同一个管理面登记——名称、形状、尺寸、启用的
签章模式。差别只在模式：

| 维度 | 素材章模式（公开层，SA2） | 签章模式（CA 背书层，SA3） |
| --- | --- | --- |
| 本质 | 一张**图片**（视觉呈现） | 图片 + **密码学绑定**（数字签名） |
| 法律效力 | 零——贴上去的图任何人都可复制，UI 角标明示 | 《电子签名法》下可能构成"可靠电子签名" |
| 安全要求 | 公开分发，无保密需求 | 私钥受控（专用/签名服务器/UKey）、审计、防复制 |
| 涉及方 | 平台方自己提供 | 必须有第三方 CA（CFCA 等工信部许可机构） |
| 管理面 | 同一印章库登记：名称/形状/尺寸/模式标记 | 同一管理面；额外登记证书指纹、启用状态、C3 锁定联动 |

《电子签名法》第十三条的可靠电子签名四条件（与欧盟 eIDAS"高级电子签名"
同构， Wikipedia 确认了这一跨法域共性）：
1. 签名制作数据**专属于签名人**；
2. 签署时制作数据**仅由签名人控制**；
3. 签署后对签名及数据内容的**任何改动能够被发现**；
4. 签署后对数据内容改动能被发现。

**推论（SA3 的硬边界）**：CatOffice 作为桌面编辑器**不能自建 CA**——私钥
托管、身份核验、时间戳全部需要工信部许可的第三方电子认证服务机构
（CFCA 模式已确认其产品形态：CA 证书 + 签名验签服务器 + 时间戳 +
UKey/云证书 + 验签平台 + 司法存证）。SA3 的正确定位是**对接方**：
本地持有 CA 颁发的证书（UKey 或云端密钥），在导出时对文档做数字签名
并把可视章图与签名值绑定呈现。

## 二、素材章模式（公开层，SA2）——签章管理模式下的低安全等级

定位与素材中心的"模板即 docx"完全平行——**印章即图片资产**，公开分发；
在签章管理模式下以"素材章"形态登记，可随时升级为 CA 背书签章（同一印章
条目补充证书绑定）。

### 内容分层

| 层 | 内容 | 来源 |
| --- | --- | --- |
| 本地内置 | 少量通用装饰章样（已有 sealPlaceholderPng 弧形字生成器可程序化生成任意机构名占位章） | 生成器代码 |
| 云目录 | 各行业样式章、圆形/椭圆/方形模板、特定风格印泥效果 | CatSpark asset_center 扩展（A3 契约已定） |
| 用户自制 | SA1 边缘检测从扫描页提取的章 + 手绘/上传 | 本地入库 |

### 功能要点

- **入库**：SA1 `detectSeal` + `cropRgba` 检测提取 → 自动形状/尺寸标注 →
  本地素材库（userData/seals/，JSONL 元数据：名称/形状/直径mm/来源）。
- **管理**：列表/重命名/删除/设为默认章。
- **插入**：骑年盖月锚定（复用 govtSealImage 落点逻辑），素材库选章替换
  占位章。
- **云目录（可选，并入 A3）**：`asset_center/seals` 端点；mock 先行。
- 明确声明（UI 角标）：素材库的章**仅为视觉呈现，无法律签名效力**。

### 工程落点

- `apps/docs/src/renderer/seal-library.ts`（元数据 CRUD）+ 设置/插入 UI。
- 测试：入库/列表/删除、检测→入库→插入闭环、云目录 mock。

## 三、签章模式（CA 背书层，SA3）——对标招投标电子文书签章

同一印章条目启用签章模式后，成为法律意义上的签名实体。

### 产品形态（对标招投标电子文书签章实践）

招投标的典型流程：投标人办理 **CA 证书**（UKey 或云端密钥）→ 标书
**在线签章**（单位章 + 法人个人章，可多章）→ 平台加**可信时间戳** →
开标后**验签**（任何改动即失效）。CFCA 的产品组合（安心签 API/SDK、
签名验签服务器、时间戳、鉴印平台）确认了行业形态。

CatOffice 对应的能力面：

| 能力 | 说明 | 依赖 |
| --- | --- | --- |
| 模式启用 | 素材章升级为签章：登记 CA 证书绑定，管理面标记该印章为"法律签名实体"（不可逆降级需审计记录） | 第三方 CA |
| 证书接入 | UKey（PC/SC）或云端证书（签章服务 API） | 第三方 CA |
| 签名 | PDF 数字签名（PAdES 基线；LTV 长效验证）/ OFD 签名（国密强制） | C4 SM3/C5 |
| 可视章图与签名绑定 | 章图位置 = 签名字段的视觉呈现（**非贴图**）——图随签名域走，改动即失效 | 签名格式 |
| 验签 | 打开已签文档显示签名域列表/证书链/时间戳/内容完整性 | 同上 |
| 多章与角色 | 单位章 + 个人章分别持钥；会话锁定（C3）期间签名不可用 | C3 |
| 审计 | 每次签名/验签入 C1 审计日志（含证书指纹，不含私钥） | C1 |

### 安全管理要求（compliance 语境）

- 私钥**永不落盘明文**：UKey 硬件内 / 签名服务器端签名（文档哈希送签）。
- 使用审计（C1）：sign/verify 事件全记录。
- 与 C3 联动：会话锁定时签名能力同时失效。
- 与 C2 的红线区分：签章行为**不属于**上传同意的门控对象（签名是本地
  操作；上传与否由用户单独决定）。
